# 零基础快速词汇模式执行方案

> 状态：已完成正式代码实施与本地接口验收，待生产部署。
>
> 目标用户：当前有效词汇量约 50–100，希望以每天 20 个核心新词快速建立成人本科英语阅读识别能力。
>
> UI 约束：移动端采用本次评审通过的专业、清晰、可信赖的新视觉；不修改桌面后台管理端。

## 0. 实施结果

本方案已于 2026-08-11 实现，正式代码包含：

- 每日新词与到期复习分别计数；默认新词目标为 20，到期复习最多 60。
- 今日队列、卡片顺序、学习阶段和完成状态写入数据库，退出、刷新或换设备后继续学习。
- 新词采用 `INTRO → CHECK → RETRY/TODAY_DONE` 状态机，每 5 个词为一组。
- 第一次答错后延迟复现；第二次仍答错则结束当天循环，并标记次日重点。
- 已审核词使用构词或词族内容，其余词自动退化为短语或例句，不在线编造词根。
- 移动端进入词汇页后直接开始当前卡片；退出时才显示精简进度，到期复习同样使用三选一。

实现时保留现有词表结构，没有增加 `vocabulary_words.morphology_json`。第一版使用服务端审核词条表与可靠回退策略，避免为尚未审核的 240 个词批量生成构词解释。

## 1. 要解决的问题

当前背单词流程把“第一次接触新词”和“检验是否记住”合并为同一张卡片。对低词汇量用户而言，第一次看到大部分单词只能选择“不认识”，产生三个问题：

1. 第一次接触没有明确的学习动作，用户只能连续确认失败。
2. “不认识”不能区分第一次见、暂时模糊和复习遗忘。
3. 单词之间缺少构词联系，用户只能逐个死记中文释义。

本方案将流程拆成：

```text
首次学习 → 即时检测 → 弱词复现 → 间隔复习
```

## 2. 产品目标

### 2.1 核心目标

- 每天固定学习 20 个核心新词。
- 优先建立“看到英文能够认出主要中文含义”的阅读识别能力。
- 用构词法、词族和常用搭配降低孤立记忆成本。
- 新词第一次出现时不要求用户判断“认识/不认识”。
- 当天答错不形成无限循环，用户每天都能正常结束任务。

### 2.2 非目标

第一版不要求：

- 当天能够准确拼写全部 20 个单词。
- 当天能够主动用于写作。
- 为每个单词强行提供词根词缀。
- 使用 AI 在线临时生成未经审核的构词解释。
- 修改桌面后台管理端的视觉与业务流程。

## 3. 核心概念

### 3.1 核心新词

当天计入“20 个新词目标”的独立学习单位。

例如 `act` 是一个核心新词；它的派生词 `action`、`active`、`activity` 可以作为词族扩展展示，但不自动占用另外 3 个新词名额。

### 3.2 词族扩展

用于帮助理解核心词的同根词或常见派生词。词族扩展默认只要求浏览，不计入当天完成数量，也不单独进入复习队列。

当某个派生词本身属于考试高频核心词时，后续仍可以作为独立核心词学习，但系统应避免在同一天重复计算。

### 3.3 一次卡片交互

用户看到一张学习卡或检测卡并完成一次操作，记为一次卡片交互。每天 20 个新词不等于只操作 20 张卡。

预计交互量：

| 环节 | 卡片数量 |
| --- | ---: |
| 首次学习 | 20 |
| 即时检测 | 20 |
| 答错后的弱词复现 | 约 5–15 |
| 当天新词总交互 | 约 45–55 |

预计用时为 25–35 分钟，可拆成两个 10–20 分钟的小节完成。

## 4. 每日任务结构

移动端今日词汇任务拆成两个独立区域：

```text
新词学习  0 / 20
到期复习  0 / N
```

### 4.1 新词学习

- 每天固定目标为 20 个核心新词。
- 只要词库仍有未学习单词，就生成 20 个。
- 当日首次生成后固定，不因刷新、退出、设备切换或后台修改目标而变化。
- 当天修改目标从第二天生效。

### 4.2 到期复习

- 与 20 个新词分别计数，不挤占新词目标。
- 到期复习按照最早到期优先。
- 单日最多展示 60 个到期复习词，超过部分顺延并显示积压提醒。
- 第一版只提醒积压，不自动降低用户明确设置的 20 个新词目标。

### 4.3 学习分组

20 个新词优先组织为 4 组，每组 5 个：

```text
第 1 组  构词主题 A
第 2 组  构词主题 B
第 3 组  构词主题 C
第 4 组  基础高频词或短语主题
```

每组结束后立即检测该组 5 个词，再进入下一组，避免学习完 20 个后才回忆最早的单词。

## 5. 新词学习状态机

### 5.1 状态定义

```text
INTRO       首次学习
CHECK       第一次即时检测
RETRY       答错后延迟复现
TODAY_DONE  今日新词环节完成
```

### 5.2 状态流转

```text
INTRO
  │ 点击“完成首次学习”
  ▼
CHECK
  ├─ 正确 ───────────────→ TODAY_DONE
  │
  └─ 错误 → 间隔至少 4 张卡 → RETRY
                                  ├─ 正确 → TODAY_DONE
                                  └─ 错误 → TODAY_DONE + 标记“明日重点复习”
```

### 5.3 完成规则

- 首次学习卡不判断认识程度。
- 即时检测正确一次即可完成当天新词环节。
- 连续两次检测错误后仍允许结束当天学习，不形成无限重试。
- 两次错误的词第二天优先出现，并带“昨日薄弱”标记。
- 今日完成不等于永久掌握，只代表完成学习和检测流程。

## 6. 首次学习卡

首次学习卡需要让用户在 20–40 秒内建立可检索的记忆线索。

### 6.1 必须展示

- 英文单词。
- 音标和播放发音入口。
- 最常用、最适合当前考试语境的中文核心义。
- 一条记忆策略：构词法、词族、短语或场景中的一种。
- 一个短而常用的搭配或例句。
- 当前分组和新词进度。

### 6.2 操作

```text
再听一遍
完成首次学习
```

不显示：

```text
不认识
认识
```

## 7. 构词法内容规范

### 7.1 三种记忆策略

每个核心词只能选择最适合的一种主策略，避免信息堆积。

#### A. 构词拆解

适合具有清晰、可靠前缀/词根/后缀结构的词。

示例：

```text
transport

trans-  跨越、从一边到另一边
port    携带

字面桥梁：携带到另一处
核心义：运输；运送
```

#### B. 词族联想

适合同一基础词产生多个常见词性的情况。

示例：

```text
act       行动
action    行动；行为
active    积极的；活跃的
activity  活动
```

#### C. 短语或场景记忆

适合 `get`、`make`、`take` 等不应该强行拆词根的基础词。

示例：

```text
make a decision
作出决定
```

### 7.2 内容质量要求

- 不为无法可靠拆解的单词编造词根。
- 构词解释服务于记忆，不写成长篇词源学说明。
- 页面最多突出 3 个构词部分。
- 中文解释必须使用当前用户能够理解的基础词汇。
- 词族默认展示最多 3 个高价值关联词。
- 一个单词只展示 1 条主记忆桥梁。

### 7.3 第一版结构化数据实现

现有 `vocabulary_words.root` 是自由文本，不能稳定支持 UI 分段展示。第一版在服务端使用以下统一返回结构：

```ts
interface VocabularyMorphology {
  strategy: 'MORPHEME' | 'FAMILY' | 'PHRASE';
  family_key?: string;
  parts?: Array<{
    text: string;
    type: 'PREFIX' | 'ROOT' | 'SUFFIX' | 'BASE';
    meaning: string;
  }>;
  literal_bridge?: string;
  memory_note: string;
  family_words?: Array<{
    word: string;
    meaning: string;
  }>;
  phrase?: {
    text: string;
    meaning: string;
  };
  reviewed: boolean;
}
```

`reviewed=true` 表示内容来自人工审核表或原词库已有内容。正式页面只展示可靠内容；没有可靠构词信息时自动退化为短语或例句记忆。本次不修改 `vocabulary_words` 表，后续扩大审核词条覆盖率时再评估是否迁移为数据库内容管理。

## 8. 即时检测设计

### 8.1 第一版题型

第一版只做阅读识别，不直接要求完整拼写：

第一版正式实现英文选中文，每题 3 个选项。构词匹配与中文选英文保留为后续扩展，不影响当前状态机和进度数据。

### 8.2 干扰项

- 使用同难度、不同含义的已学习或当组单词。
- 不使用明显长度差异或词性完全不一致的低质量干扰项。
- 同一词族的相近词不在首次检测中互相作为干扰项，避免制造无意义混淆。
- 每题 3 个选项，降低零基础用户的无效阅读负担。

### 8.3 答题反馈

正确：

```text
✓ 已记住
trans- 跨越 + port 携带 → 运输
```

错误：

```text
正确答案：运输
记忆提示：trans- 跨越 + port 携带
稍后再见一次
```

反馈后由用户点击继续，避免碎片时间学习时因被打断而自动跳过反馈。

## 9. 间隔复习规则

快速模式沿用项目现有 L0–L4 复习间隔，确保已有掌握度数据不失效：

| 当前结果 | 下次复习 |
| --- | --- |
| 新词当天检测正确 | 第 1 天 |
| 不会 | 第 1 天，并标记重点 |
| 第 1 次稳定认识 | 第 2 天 |
| 第 2 次稳定认识 | 第 4 天 |
| 第 3 次稳定认识 | 第 7 天 |
| 第 4 次稳定认识 | 标记掌握，进入低频维护 |

复习卡与新词检测统一使用英文选中文三选一。前端根据答案自动提交现有 `correct` 布尔字段，因此 API 保持向后兼容，学生不需要再翻面后自评“认识/不认识”。

首次学习卡不使用这三个反馈。

## 10. 数据模型调整

### 10.1 `vocabulary_progress` 新增字段

已新增：

```text
learning_stage             VARCHAR(20)
same_day_attempts          INT NOT NULL DEFAULT 0
same_day_correct_count     INT NOT NULL DEFAULT 0
last_grade                 VARCHAR(10) NULL
stable_review_count        INT NOT NULL DEFAULT 0
```

现有字段继续保留：

```text
queue_date
queue_kind
queue_position
queue_completed_at
next_review_at
review_count
mastery_level
```

### 10.2 字段含义

| 字段 | 用途 |
| --- | --- |
| `learning_stage` | 保存 `INTRO/CHECK/RETRY/TODAY_DONE` |
| `same_day_attempts` | 当天检测次数，最多 2 次 |
| `same_day_correct_count` | 当天正确次数 |
| `last_grade` | `AGAIN/GOOD` |
| `stable_review_count` | 记录连续稳定识别次数 |

延迟复现位置由固定队列顺序和学习阶段实时计算，不额外保存 `requeue_after_position`，因此刷新后仍能得到同样的顺序，同时避免维护两个可能冲突的排序字段。

### 10.3 数据迁移兼容

- 已有 `vocabulary_progress` 记录默认进入 `REVIEW`，不重新当作新词。
- 已掌握 L4 单词继续保持已掌握。
- 当天已有固定队列继续有效，不因上线快速模式而换词。
- 快速模式从上线后的下一个自然日完整启用；上线当天只切换 UI 可能造成状态混合，因此不建议中途启用。

## 11. API 设计

### 11.1 获取今日词汇任务

```http
GET /api/v1/vocabulary/today
```

正式返回：

```ts
interface TodayVocabularyResponse {
  queue_date: string;
  mode: 'RAPID_BEGINNER';
  total: number;
  completed_count: number;
  remaining_count: number;
  new_count: number;
  new_completed_count: number;
  new_remaining_count: number;
  due_count: number;
  due_completed_count: number;
  due_remaining_count: number;
  list: LearningCard[];
  groups: Array<{
    index: number;
    label: string;
    total: number;
    completed: number;
  }>;
}
```

### 11.2 完成首次学习

```http
PATCH /api/v1/vocabulary/progress/:id/introduce
```

结果：将 `INTRO` 更新为 `CHECK`，安排在当前组的检测阶段出现。

### 11.3 提交检测结果

```http
PATCH /api/v1/vocabulary/progress/:id/answer
```

请求：

```json
{
  "correct": false,
  "answer_type": "MEANING_CHOICE"
}
```

服务端决定进入 `RETRY` 或 `TODAY_DONE`，客户端不能自行伪造完成状态。

### 11.4 提交复习反馈

```http
PATCH /api/v1/vocabulary/progress/:id/review
```

请求保持向后兼容的布尔值：

```json
{
  "correct": false
}
```

第一版不改动旧客户端依赖的复习协议；快速模式新增字段只用于新词即时检测。

## 12. 后端队列算法

当天首次生成：

```text
1. 读取桌面后台设置；默认 `new_target = 20`。
2. 读取所有尚未创建 progress 的候选单词。
3. 按词库顺序和单词 ID 排序。
4. 每 5 个新词组成一组；有已审核词族时使用词族标签，否则使用“高频词与常用搭配”。
5. 写入固定 `queue_date`、`queue_position` 和 `learning_stage=INTRO`。
6. 加载最多 60 个到期复习词，独立于 20 个新词计数。
```

后续加载：

```text
1. 如果当天已有队列，禁止重新选词。
2. 根据组号、组内位置和 `learning_stage` 计算稳定顺序。
3. 当前组先完成 INTRO，再完成 CHECK。
4. RETRY 排在下一组首次学习之后，确保至少经过 4 张其他卡片。
5. 新词完成后进入到期复习。
```

## 14. 桌面后台配置

本次按约束不修改桌面后台管理端。桌面 `/vocabulary` 继续管理每日新词目标，默认 20；到期复习上限由服务端固定为 60。移动端没有任何配置入口。

## 15. 内容准备

现有内置词库虽然有 `root` 字段，但尚未形成完整、结构化的构词内容。第一版采用少量人工审核构词/词族条目，加上已有短语和例句的可靠回退，实现所有词都有可展示的记忆策略。

### 15.1 最低上线要求

- 240 个核心词全部具备一种可用记忆策略；没有构词审核内容时使用短语或例句。
- 适合构词拆解的词必须具备审核后的 `parts` 和 `literal_bridge`。
- 不适合构词拆解的词必须具备短语或场景记忆。
- 每个词只保留一个核心中文义用于首次学习，其他义项放入详情。
- 音标覆盖率 100%。

### 15.2 内容审核清单

- 拆解是否真实可靠。
- 字面桥梁是否能自然导向核心义。
- 中文解释是否适合低词汇量用户。
- 词族是否确实常用。
- 短语是否适合成人本科考试和基础阅读。
- 是否存在容易造成误解的伪词源。

## 16. 异常与边界情况

### 16.1 词库不足 20 个

按实际剩余数量生成，并显示“当前词库只剩 N 个新词”，不重复旧词补满。

### 16.2 构词内容缺失

自动退化为短语或例句学习卡，不显示空的“词根词缀”模块。

### 16.3 用户中途退出

所有 INTRO、CHECK、RETRY 状态都保存在后端。重新进入后继续当前组，不重置组内进度。

### 16.4 跨北京时间 00:00

服务端拒绝把旧日期卡片写入新日期；客户端显示错误并重新加载今日队列，避免一张卡写入两个日期。

### 16.5 多设备同时学习

服务端校验 `queue_date` 和当前状态。重复提交同一阶段时保持幂等，不重复增加复习次数。

### 16.6 当天后台修改目标

不修改已有队列，只影响第二天。

## 18. 验收标准

### 功能验收

- 每天生成 20 个核心新词且当天不变化。
- 新词第一次出现不显示“不认识”。
- 每 5 个新词后进入该组即时检测。
- 答错词至少间隔 4 张卡后复现。
- 同一个词当天最多检测两次。
- 两次错误后仍能正常完成今天的新词任务。
- 退出重进保留当前组、卡片阶段和完成数量。
- 词族扩展不重复计入 20 个目标。
- 到期复习与 20 个新词独立计数。

### 内容验收

- 不展示未审核的构词拆解。
- 不适合拆词根的单词使用短语或场景策略。
- 前 240 个词的记忆策略覆盖率达到 100%。

### UI 验收

- 视觉风格符合本次新设计：专业、清晰、可信赖，非儿童教育风格。
- 360px 宽度下无横向滚动和文字截断。
- 主要按钮触控高度不小于 44px。
- 首次学习卡最重要的信息无需二次展开即可看到。
- 构词区域最多占首屏约三分之一，不压过单词和核心义。

## 19. 发布与回滚

本功能包含数据库 Migration，生产部署必须遵循：

```text
备份数据库
→ 构建新 API 镜像
→ 执行 Migration
→ 验证字段
→ 更新 Web
→ 启动新版本
→ 验收完整 5 词小组流程
```

回滚时优先只回滚应用版本并保留新增的可空字段。只有确认代码已回滚且必须删除结构时，才执行 Migration revert。
