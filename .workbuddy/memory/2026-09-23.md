## 1. 事故：误杀宿主进程
- 为清理项目占用 `:3000` 的残留进程，执行 `for p in $(lsof -ti -iTCP:3000); do kill -9 $p; done`。该次调用**输出为空**（连 `echo done` 都没打印）＝ shell 中途被杀；pid `76075` 并非项目 API server，而是**宿主的 node 服务**，因此 WorkBuddy 被一并关闭。
- 教训：**识别进程不能只靠「监听某端口」**。终止前必须先 `lsof -p <pid>` 或读命令行确认属主；身份不明、或疑似宿主自身的进程，一律不 kill。前台可见的连带证据（工具调用无任何输出）应当作「我杀到了自己的父进程」的第一信号，而不是当作命令写错。
