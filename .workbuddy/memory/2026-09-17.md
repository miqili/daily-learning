## 打包链路改造：Dockerfile.server 改为本地预构建（完成）

背景：服务器配置低，`docker compose build` 时 `pnpm install --frozen-lockfile` + `nest build` 跑不动，要求与 `Dockerfile.web` 一样「镜像只做打包运行」。

改动（只动 `docker/Dockerfile.server`，保留原 2 阶段版已备份思路）：
- 删除 `builder` 阶段（corepack/pnpm install/nest build 全部搬到本地）。
- 运行时镜像 `node:20-alpine`，只 COPY 预构建产物：`node_modules`（含 pnpm 虚拟 store `.pnpm`）、`packages/shared/{package.json,dist}`、`packages/server/{package.json,dist,node_modules}`，`CMD node packages/server/dist/main.js`。
- 前提命令（已写入 Dockerfile 注释）：本地先 `pnpm install --frozen-lockfile && pnpm build:shared && pnpm --filter @shck/server build`。

关键依据（已核验）：
- pnpm 依赖是**相对路径软链**（`packages/server/node_modules/bcryptjs -> ../../../node_modules/.pnpm/...`），COPY 保软链、必须保相对结构，故不能只拷 dist。
- `packages/server/node_modules/@shck/shared -> ../../../shared`，shared 入口 `dist/index.js`，故 shared 的 package.json + dist 都要带上。
- `packages/server/src` 无运行期非 TS 资源（nest-cli 未配 assets），dist 内无 json/sql 等外部文件 → 不需要额外资产。
- pnpm store 内 **零 `.node` 原生二进制**（bcryptjs/mysql2 均纯 JS）→ macOS 侧 node_modules 可直接跑在 alpine，无跨平台 ABI 风险。
- 代价：镜像内含完整 node_modules（本地实测 459MB，含各包 devDeps）→ 镜像约 600MB 级；如需瘦身可另做 `pnpm install --prod` 方案（未做，用户要求不再引入构建步骤）。

## 修正：服务器可以 install，只是不能 build（Dockerfile.server 最终版）
- 用户澄清并给出真实报错：`COPY node_modules` / `COPY packages/server/node_modules` 双双 ERROR（其余 COPY 命中缓存）→ 服务器项目目录里没有 node_modules（dist 已存在）。结论：**install 允许在容器内做，只要不在镜像里 build**。
- 最终 `docker/Dockerfile.server`（单阶段 node:20-alpine）：`RUN corepack enable` → 只拷 `package.json/pnpm-lock.yaml/pnpm-workspace.yaml` + `packages/{shared,server}/package.json` → `RUN pnpm install --frozen-lockfile` → `ENV NODE_ENV=production` → 拷 `packages/shared/dist` + `packages/server/dist` → `CMD node packages/server/dist/main.js`。
- 两个设计取舍：① 依赖清单与 dist 分两层 COPY，改代码不会重装依赖；② **NODE_ENV=production 刻意放在 install 之后**，避免 pnpm 因 `NODE_ENV=production` 跳过 devDeps 而改变安装行为（与既有可用镜像保持一致，devDeps 里没有任何运行期必需品）。
- install 时 workspace 会建好 `packages/server/node_modules/@shck/shared -> ../../../shared` 软链，故只需补 shared 的 dist 入口，**不需要再同步 node_modules 到服务器**。
- 未采纳的优化：`pnpm install --prod`（可省 vite/rollup/typescript 等 devDeps，明显省内存）。用户要求不做任何测试，故保留已验证的原始安装命令；若 install 在服务器上仍然吃紧，改这一处即可。
- 硬前提：`packages/shared/dist`、`packages/server/dist` 必须在服务器构建上下文里（dist 被 .gitignore 排除，需本地 build 后同步，与 web 的 packages/web/dist 同一套做法）。

## PC 必背考点「高等数学一」裸 \quad 修复
- 现象：章节正文里出现大量 `\quad`、`\qquad` 源码字面量（`3.1\quad 先定保底线`、`2024 第 6/7/8 题\quad 2025 …`、`……$\quad <span>2025 选择第 11 题</span>`、`<br>\quad 例：…`）。
- 根因：这些间距命令写在**数学定界符之外**（`$…$`/`$$…$$` 之外），KaTeX 的 `renderToString`（display 裸 LaTeX）与 `auto-render`（只扫文本节点里的定界符）都不会处理它们 → 原样透出。数据源 `builtin-must-read.ts` 的章节正文是机器生成的 HTML，不手改。
- 修复（渲染层，单点收口）：新增 `packages/web/src/utils/texSpacing.ts` → `normalizeBareTexSpacing()`：逐字符扫描，跳过 `$$…$$`/`$…$` 段，把定界符之外的 `\qquad/\quad/\enspace/\;/\:/\,\,` 换成语义化间隔元素 `<span class="tex-gap is-*" aria-hidden="true">`；`\\` 不参与匹配。
- 接入 3 处：`KatexHtml.vue`（computed 归一化后再 auto-render）、`KatexRenderer.vue` 文本段（**必须先 escapeHtml 再归一化**，否则插入的 span 被转义）、`utils/markdown.ts` 的 `renderBase`（题干/解析同步受益）。`display` 裸 LaTeX 分支**不归一化**。
- 样式：`assets/design-system.css` 新增 `.tex-gap` 段（width 2em/1em/.5em/.278em/.222em/.167em，对齐 LaTeX 原生宽度），全局生效（v-html 内容不吃 scoped）。
- 校验（只读脚本，非页面测试）：对 `builtin-must-read.ts` 全部 280 个 content 字段跑归一化——数学段总字符数前后完全一致（公式零改动），定界符外裸间距命令 103 → 0。

### 追加：`$x\to 0$` 这类「公式没渲染」的同类问题（同一页）
- 追问来源：`$x\to 0$` 不是间距命令，而是**整个公式都没走 KaTeX**——因为这些字段在模板里是 `{{ }}` 纯文本插值。
